**Semantic hints for Usage Notes (use source-lms-events.md + event attribute shapes; keep prose factual, do not invent behavior):**

- `Camera_Changed` — fires when the 3D camera position changes. Consumers can use the 6 coordinates to save camera state or sync with other views.
- `Component_Transformed` — fires when a component is transformed (sized, rotated, or positioned — `type` disambiguates). `data` carries the transform payload. Element_Verify has the verification flags.
- `Element_Verify` — fires in response to `verifyElement()` calls (or internal checks). Reports visibility/load/enabled state for a named element. Used for post-add assertion. The commented-out `isIsolated` in source suggests a planned but inactive attribute; documentation must note this so developers don't expect it in payloads.
- `Group_Transformed` — fires when a group of components is transformed as a unit. Carries only `model:Object` — the group model payload.
- `Input` — fires for various input-driven actions (change, focus, focuslost). `type` disambiguates. `metadata` carries action-specific context.
- `LabelStyling_Closed` — fires when the label-styling panel is dismissed without changes. Signals UI consumers to collapse/hide.
- `LabelStyling_Updated` — fires when label styling is committed. All 7 style properties carried.
- `Mesh_Hovered` — fires when the pointer hovers over a 3D mesh. Parallel to Mesh_Selected but for hover. Consumers can show preview popups or highlight related records.
- `RelatedRecord_Fetched` — fires when `RelatedRecord` lookup completes. `data` carries the record; `foundRecord` disambiguates miss vs hit.
- `Settings_Fetched` — fires when scene settings have been fetched from the server. `settings:Object` carries the payload.

**Style constraints (observed across existing events-aura pages):**

- Top `#` and `###` headings use escaped underscores: `EVT\_Renderer\_Foo`
- Section subheadings use `####` (not `###`)
- Table columns observed: NAME / TYPE / REQUIRED / DESCRIPTION (for pages that show required), or NAME / TYPE / DESCRIPTION (simpler pages). Use REQUIRED column only when the event has `access=global` on its attributes and thus the required flag is meaningful.
- Example Usage omitted when the event is fire-and-forget with no useful handler example. `evt_renderer_screenshot_taken.md` precedent: just parameters, no example. Follow this precedent for events without obvious consumer-facing usage (e.g., Group_Transformed's `model` is an internal shape — skip Example Usage).
- Include Example Usage (Component + Controller blocks) for events where handlers are practically useful: Camera_Changed, Component_Transformed, Element_Verify, Mesh_Hovered, RelatedRecord_Fetched, LabelStyling_Updated, Input, Settings_Fetched.
- Skip Example Usage (stop after Event Name) for: LabelStyling_Closed (empty-param dismissal signal), Group_Transformed (internal model shape).
