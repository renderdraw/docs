**Key facts from Phase 1 inventories:**

- 56 Aura events total; 33 are public-facing (the 23 `EVT_Settings_*` events are internal — exclude).
- All 56 events are APPLICATION type — any component in the namespace can fire or handle them.
- 14 events have `access="global"` (accessible across namespaces). 1 (`EVT_Renderer_Input`) uses `access="public"`. The remaining 18 public events use default (which is effectively `global` within the managed-package namespace).
- Firing pattern in Aura: `var evt = $A.get("e.RDraw:EVT_Name"); evt.setParams({...}); evt.fire();`
- Firing pattern in LWC (rare for RDraw:EVT_* since LMS is preferred): `this.dispatchEvent(new CustomEvent('...'))` — note that LWCs dispatch DOM events, not Aura app events. RDraw:EVT_* events are predominantly fired from Aura controllers/helpers.
- Handling pattern in Aura: `<aura:handler event="RDraw:EVT_Name" action="{!c.handleFoo}" />`

**Constraining decisions (from PROJECT.md):**

- Public API surface only — exclude the 23 internal `EVT_Settings_*` events from the mapping.
- No restructuring — this plan produces an inventory file in `.planning/phases/03-aura-events/`, not in GitBook.

**Pattern to establish (for Plans 03-02 through 03-04):**

The mapping file produced by this plan will drive per-page enrichment. Each documented event page will gain three new sections (appended after the Parameters table, before any Example Usage):

1. **Source Component:** — bulleted list of Aura/LWC component names that fire this event.
2. **Handler Component:** — bulleted list of component names that register `aura:handler` for this event. If no in-package handlers found, note "None in main package — consumed by external implementing components."
3. **Event Name (for handler):** — fenced code block with the `RDraw:EVT_Name` string usable in `<aura:handler event="..."/>`.

This mirrors Phase 2's Publisher/Subscriber bulleted pattern. See `.planning/phases/02-lms-message-channels/02-01-SUMMARY.md` → `patterns-established`.
